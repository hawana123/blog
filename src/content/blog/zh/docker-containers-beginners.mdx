2019年我第一次接触Docker时，花了三周时间才理解它到底做了什么。文档谈到"容器化"、"镜像"和"层"，但直到我构建了真实的东西，一切才 click。从那以后，我在三家公司 onboarding 了大约30位初级开发者使用Docker。本指南中的方法是 consistently 有效的。

这不是参考手册。而是一条学习路径，带你从零到自信地运行容器化应用。

## Docker到底做什么（用大白话讲）

在Docker之前，部署应用是痛苦的。你的代码在你的笔记本上运行正常，但在服务器上失败，因为服务器有不同版本的Node.js、缺少系统库，或与其他应用有冲突的依赖。

Docker通过将你的应用与运行它所需的一切——代码、运行时、系统工具、库和设置——打包到一个称为容器的单一单元中来解决这个问题。这个容器在你的笔记本、测试服务器和生产环境上 identical 运行。

把它想象成运输一个完整的、自包含的电器，而不是零件清单和说明书。收件人不需要知道如何组装任何东西。他们只需插上电源。

## 你的第一个容器

从docker.com安装Docker Desktop。安装完成后，打开终端并运行：

```bash
docker run hello-world
```

这会下载一个最小镜像并运行它。输出解释了Docker刚刚做了什么：它检查了本地镜像，没找到就从Docker Hub下载，然后运行了容器。这个单一命令展示了整个Docker工作流。

### 理解发生了什么

这里有三个概念在起作用：
1. **镜像**：一个只读模板，包含创建容器的指令。`hello-world`镜像包含一个打印消息的小程序。
2. **容器**：镜像的可运行实例。当你运行 `docker run` 时，Docker从 `hello-world` 镜像创建了一个容器。
3. **Docker Hub**：存储和共享镜像的 registry。当本地没找到镜像时，Docker从Hub拉取它。

## 构建你自己的镜像

运行现有镜像很有用，但真正的力量来自构建自己的镜像。创建一个新目录并添加两个文件。

`app.py`：
```python
from flask import Flask
app = Flask(__name__)

@app.route('/')
def hello():
    return "Hello from Docker!"

if __name__ == '__main__':
    app.run(host='0.0.0.0', port=5000)
```

`Dockerfile`：
```dockerfile
FROM python:3.11-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install -r requirements.txt
COPY . .
EXPOSE 5000
CMD ["python", "app.py"]
```

`requirements.txt`：
```
flask==3.0.0
```

构建镜像：
```bash
docker build -t my-first-app .
```

`-t` 标志用名称标记镜像。`.` 告诉Docker在当前目录中查找Dockerfile。你会看到显示构建过程每一步的输出。注意Docker如何缓存层——如果你在不更改 `requirements.txt` 的情况下重新构建，`pip install` 步骤会被跳过，因为它已经被缓存。

运行你的容器：
```bash
docker run -p 5000:5000 my-first-app
```

`-p 5000:5000` 将主机上的5000端口映射到容器中的5000端口。访问 `http://localhost:5000`，你会看到你的应用正在运行。

## 你每天会用的基本命令

| 命令 | 用途 |
|---|---|
| `docker ps` | 列出运行中的容器 |
| `docker ps -a` | 列出所有容器（包括已停止的） |
| `docker images` | 列出本地镜像 |
| `docker stop <id>` | 停止运行中的容器 |
| `docker rm <id>` | 移除已停止的容器 |
| `docker rmi <id>` | 移除镜像 |
| `docker logs <id>` | 查看容器输出 |
| `docker exec -it <id> /bin/sh` | 在运行中的容器内打开shell |

`docker exec` 命令对调试特别有用。当容器行为不符合预期时，在其中打开shell可以让你检查文件系统、检查环境变量并运行诊断命令。

## 卷：持久化数据

容器按设计是短暂的。当容器停止时，写入其中的任何数据都会消失。这是一个 feature，不是 bug——它确保一致性和可重现性。但大多数应用需要持久化存储。

Docker用卷来解决这个问题。卷是容器文件系统之外的目录，由Docker管理。创建一个：

```bash
docker volume create my-data
```

用挂载的卷运行容器：
```bash
docker run -v my-data:/data my-first-app
```

现在写入容器内 `/data` 的任何内容都会持久化到卷中。即使容器被移除并重新创建，数据也会保留。

对于开发，我更喜欢 bind mount，它将主机目录直接映射到容器中：
```bash
docker run -v $(pwd):/app my-first-app
```

这让你在主机上编辑代码并立即在容器内看到更改，而无需重新构建镜像。

## Docker Compose：多容器应用

真实应用很少由单个容器组成。一个典型的Web应用需要应用服务器、数据库，可能还有缓存或消息队列。用 `docker run` 命令手动管理这些变得笨拙。

Docker Compose在YAML文件中定义多容器应用。以下是一个带有PostgreSQL的Flask应用的真实示例：

`docker-compose.yml`：
```yaml
version: '3.8'

services:
  web:
    build: .
    ports:
      - "5000:5000"
    volumes:
      - .:/app
    environment:
      - DATABASE_URL=postgresql://user:pass@db:5432/mydb
    depends_on:
      - db

  db:
    image: postgres:15-alpine
    volumes:
      - postgres_data:/var/lib/postgresql/data
    environment:
      - POSTGRES_USER=user
      - POSTGRES_PASSWORD=pass
      - POSTGRES_DB=mydb

volumes:
  postgres_data:
```

启动所有内容：
```bash
docker-compose up
```

这会从你的Dockerfile构建web服务，拉取PostgreSQL镜像，创建连接服务的网络，并启动所有内容。`depends_on` 确保数据库在web应用之前启动。

## 常见初学者错误

在反复教授Docker后，我看到了相同的错误：

**在容器内以root运行。** 默认情况下，容器以root运行。如果攻击者入侵了你的应用，他们在容器内拥有root访问权限。通过在Dockerfile中创建非root用户来修复这个问题：
```dockerfile
RUN useradd -m myuser
USER myuser
```

**臃肿的镜像。** 使用 `python:latest` 或 `ubuntu:latest` 作为基础镜像包含了你应用不需要的数百兆软件包。使用slim或alpine变体。`python:3.11-slim` 镜像是45MB，对比完整镜像的900MB。

**硬编码配置。** 永远不要把数据库凭证、API密钥或环境特定设置放在Dockerfile中。使用在运行时注入的环境变量。这使相同的镜像可以在开发、 staging 和生产环境中运行。

**忽略 .dockerignore。** 没有 `.dockerignore` 文件，Docker会将你的整个项目目录复制到构建上下文中，包括 `node_modules`、`.git` 和本地配置文件。这减慢了构建速度，并可能意外包含敏感数据。

## 走向生产

对于生产部署，需要考虑额外的因素：

**健康检查**告诉Docker你的应用是否真正在工作，而不仅仅是运行：
```dockerfile
HEALTHCHECK --interval=30s --timeout=3s \
  CMD curl -f http://localhost:5000/health || exit 1
```

**资源限制**防止单个容器消耗所有主机资源：
```bash
docker run -m 512m --cpus=1.0 my-first-app
```

**日志策略：** Docker默认捕获stdout/stderr，但对于生产环境，配置一个日志驱动，将日志发送到CloudWatch或Splunk等集中式系统。

**编排：** 对于多台主机，你需要Kubernetes或Docker Swarm。这些是高级主题，但首先理解Docker fundamentals 会让过渡 significantly 更容易。
